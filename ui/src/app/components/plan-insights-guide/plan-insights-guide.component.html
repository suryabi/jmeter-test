Reference for insight rule syntax. Templates add a new rule to the list and close this dialog.

How it works
  1. Groovy scripts in the plan write lines to jmeter.log.
  2. After a run, the runner scans the log and applies these rules in order.
  3. Matching rules update entities (requests, presenters, topics…) and workflow steps.
  4. kind=ui rules control labels and lists on the run detail Insights tab.
Rule kinds
scope_open
Start a repeating entity (e.g. Request 2/5). Sets index/total and optional first step.
field
Capture a property on the active entity from a regex capture group.
step
Append a workflow timeline entry under the current scope.
run_field
Set a run-level value (date range, planned counts) outside entity scopes.
summary
Aggregate entity counts by status for the Insights summary row.
ui
Presentation only — field labels, entity picker titles, detail columns.
Common tags
entity= request, presenter, topic scope= run, request, presenter, topic match=`…` regex against log line label=`…` step text ($index, $total, field names) set= + group=N capture group → field link.index=$1 tie step/field to entity index onlyIfEmpty=true first match wins counts= created,failed,skipped,started
Examples
BIQ — open request 
kind=scope_open entity=request match=`Request (\d+)/(\d+) Creation Started` index=$1 total=$2 status=started
Presenter — open on plan line 
kind=scope_open entity=presenter match=`Presenter #(\d+): will be assigned` index=$1 total=$presentersPlanned status=started
Scoped workflow step 
kind=step scope=presenter match=`Presenter created (\d+)/(\d+) id=(\S+)` link.index=$1 label=`Presenter $index/$total created` status=success

Tips
  • Wrap regex or labels that contain spaces in backticks: match=`…`.
  • Emit stable log lines from Groovy — insights only see what the plan logs.
  • Use scope_open early on a planning line if success lines may never appear (e.g. 409 failures).
  • Plans in use by a running test cannot be saved until the run finishes.
